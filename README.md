# IslandSpeed 1.2.1 · 日常使用版

版本 1.2.1，构建号 15。基于 1.2.0（含 build-fix、closure-fix）。覆盖本包同名文件，保留其他文件及已经正常工作的 `.github/workflows/build.yml`（`runs-on: xcode-27`）。仍从 Actions Artifacts 下载 unsigned IPA，不创建 Release。

## 接力
- 删除三种预约时序及自行计时实验。保留定位辅助、采样、防抖、定宽显示、长按展开、iOS 27 `.main` 主程序路由。
- 立即接力：单次 Intent 只创建一个即时活动；4个预约时先取消最远预约释放名额，保留其余预约。成功后切换 ID、运行计时归零、累计接力+1。不再在同一次 Intent 中反复请求预约。
- 重排预约：每次独立点击只创建一个符合当前活动启动时间网格的未来预约；优先最早缺失的目标。已满4个时先取消最远且不符合新时间表的预约，成功确认取消后才创建新预约。失败保留其余预约，已释放的一个名额可能暂时无法补回。全部匹配时不再创建。若原目标已经过去，按当前活动启动时间网格跳过过期时点。
- 预约数量和重排进度分别展示；倒计时始终对应实际最早预约（不虚构重置）。一般立即接力后需最多4次独立重排点击。若期间发生另一次接力或目标过期，目标时间表会改变。
- 返回前台：满60秒沿用即时重建及完整前台重排；未满60秒也按当前活动的启动时间自动重排，无需创建新的即时活动。队列已经完全匹配时不重复创建。
- 预约间隔在停止监控后调整。自动预约正常接力不清空队列；新活动仍可持续采样更新。

## 测试
先在4/4时点击立即接力，确认活动 ID 和累计接力变化。不要返回 App，依次点击重排预约（每次待状态更新），查看重排进度及实际倒计时是否按新活动启动时间对齐。再测试返回前台时自动重排。后台满额取消旧预约后再创建能否持续得到授权仍需真机验证。

本地验证：Swift 两种目标宏条件语法解析、Shell/YAML 配置检查；直接编译并运行 RelaySchedule 的时间表与单步选择测试（0~4旧预约、过期目标、部分匹配、失败后重试模型）。未执行 iOS SDK 完整类型检查、Xcode 编译或真机测试。
